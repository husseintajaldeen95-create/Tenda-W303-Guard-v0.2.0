# Tenda W303 Guard — الإصدار 0.2.11

تطبيق Android بلغة Java لمراقبة أجهزة راوتر Tenda W303R V3.0، Firmware `V5.07.46_en`.

## الجديد في 0.2.11 — Static Assignment & IP Conflict Guard

- قراءة جدول `Static Assignment` بصورة مستقلة عن جدول `DHCP Client List` داخل صفحة `/lan_dhcp_clients.asp`، حتى عندما يكون جدول الحجوزات فارغاً.
- عرض عدد الحجوزات الثابتة وحالة كل حجز: مستخدم من الجهاز نفسه، غير ظاهر حالياً في DHCP، أو تعارض محتمل مع جهاز آخر.
- إظهار عنوان IP المحجوز الثابت داخل بطاقة المشترك مع مقارنته بعنوان DHCP الحالي، دون الخلط بين الإيجار الحالي والحجز الدائم.
- إضافة فاحص حجز جديد يقبل آخر مقطع من IP مثل `110` أو العنوان كاملاً، ويتحقق من صحة MAC ومن أن IP ضمن شبكة الراوتر.
- منع اقتراح IP يستخدمه جهاز آخر في آخر قراءة DHCP، أو محجوز لعنوان MAC مختلف، أو منع تكرار حجز IP نفسه، أو إنشاء حجز ثانٍ لعنوان MAC لديه حجز مختلف.
- السماح باستخدام IP الحالي للجهاز نفسه إذا كان MAC مطابقاً، مع توضيح حالة الحجز الموجود مسبقاً.
- بعد نجاح الفحص، يملأ التطبيق حقول Static Assignment في واجهة الراوتر فقط. لا يضغط `Add` أو `OK` ولا يحفظ إعدادات الراوتر تلقائياً؛ يراجع المستخدم البيانات ويؤكدها يدوياً.
- أضيفت اختبارات JVM مستقلة للتحقق من قواعد منع التعارض في `tests/run_ip_reservation_tests.sh`.
- بقي ملف `.github/workflows/android.yaml` دون تعديل.

## الجديد في 0.2.10 — Router Login & HTTP Authentication Fix

- يعيد التطبيق فتح عنوان الراوتر الأساسي `http://<router-ip>/` أولاً بدلاً من الانتقال المباشر إلى `/advance.asp`.
- يعالج مصادقة HTTP التي يستخدمها دليل Tenda W303R عند فتح عنوان الراوتر، ويعرض نافذة دخول داخل التطبيق لاسم المستخدم وكلمة المرور؛ لا يتم تجاوز شاشة المصادقة ولا حفظ كلمة المرور داخل التطبيق.
- إصلاح لوحة إدخال عنوان الراوتر لتقبل الأرقام والنقاط، مع إظهار لوحة مفاتيح رقمية تسمح بكتابة IPv4.
- توضيح أن الحقل يتطلب عنوان IP فقط مثل `192.168.0.1`، وليس رابطاً كاملاً مثل `http://192.168.0.1/advance.asp`.
- زر «صفحة الدخول إلى الراوتر» يعيد إلى `/` ويطلب بيانات الدخول مجدداً.
- تحسين التحقق من IPv4 بفحص كل مقطع من 0 إلى 255 بدلاً من الاعتماد على محلل عناوين النظام.
- لم يتغير ملف `.github/workflows/android.yaml`.

## الجديد في 0.2.8 — Verified Router Paths

- `Wireless > Access Control` هو مسار MAC Access Control المؤكد: `/wireless_filter.asp`، ويتحكم بمن يستطيع الانضمام إلى شبكة Wi-Fi.
- `Security` يفتح صفحة URL Filtering بالمسار `/firewall_urlfilter.asp`، وليس صفحة MAC Filter. تحتوي الصفحة التي فُحصت على Start IP وEnd IP وURL Character String والوقت وأيام الأسبوع وخيار Enable.
- `Tools > Time Settings` يستخدم المسار الذي أعلنته قائمة الراوتر `/system_hostname.asp`. تم تصحيح المسار القديم `/system_time.asp`؛ لم تُفحص حقول صفحة الوقت بعد، لذلك لا يرسل التطبيق أي تغييرات إليها.
- أزيل المسار غير الصحيح `/firewall_macfilter.asp`، وأصبح اختصار الشاشة الرئيسية واضحاً: «تصفية المواقع وجدولة الوصول».
- تحسين مسار الرجوع من التبويب الرئيسي: يتحقق التطبيق مما إذا كان التبويب يفتح صفحة الهدف مباشرة قبل محاولة البحث عن عنصر فرعي.
- ملف `.github/workflows/android.yaml` بقي كما هو دون تعديل.

## الميزات الموجودة في 0.2.5 — Traffic Statistics Monitor

- إضافة لوحة مستقلة لقراءة صفحة QoS > Traffic Statistics.
- إضافة اختصار لفتح QoS ثم Traffic Statistics من واجهة الراوتر داخل WebView.
- قراءة جدول Traffic Statistics من الصفحة الحالية أو أي iframe من نفس مصدر الراوتر.
- التعرف على أعمدة IP Address وUplink Rate وDownlink Rate وSent Bytes وReceived Bytes، مع قراءة عدادات الحزم إن كانت موجودة.
- ربط كل صف بعنوان IP مع أحدث سجل DHCP متاح، أو آخر سجل معروف خلال 24 ساعة عند غياب القراءة الحديثة، مع تمييز السجل التاريخي.
- عرض معدلات الرفع والتنزيل بوحدة KB/s وإجماليات Sent وReceived بوحدة MB وعدد الحزم.
- تحسين فحص الصفحة بحيث يعرض عناوين الجداول ومعاينة الصفوف حتى للجداول غير المعروفة سابقاً.
- قراءة تلقائية اختيارية عند تحميل صفحة الراوتر، مع بقاء زر القراءة اليدوية متاحاً.
- جميع عمليات هذا الإصدار للقراءة فقط؛ لا يغيّر إعدادات الراوتر ولا ينفذ حظراً أو QoS.

## طريقة تشغيل المراقبة الحية

1. اتصل بشبكة Tenda وافتح التطبيق وسجّل الدخول داخل WebView.
2. اضغط `فتح QoS ثم Traffic Statistics`. يستخدم التطبيق المسار المحلي المتحقق `/sys_iptAccount.asp` داخل إطار المحتوى. إذا لم يفتح تلقائياً، افتح تبويب QoS ثم Traffic Statistics يدوياً.
3. تأكد من تفعيل `Enable Traffic Statistics` في الراوتر وحفظ الإعداد عند الحاجة.
4. اضغط `بدء المراقبة الحية`. يبدأ التطبيق بفاصل افتراضي قدره 3 ثوانٍ.
5. لتغيير الفاصل اضغط زر `فاصل التحديث` للتبديل بين 3 و5 و10 ثوانٍ.
6. اختبر التغير بتنفيذ تنزيل أو رفع فعلي من أحد أجهزة الشبكة، وراقب سرعة ذلك الجهاز في بطاقة المشترك.
7. اضغط `إيقاف` عند الانتهاء. تتوقف المراقبة مؤقتاً عند إرسال التطبيق إلى الخلفية وتستأنف عند العودة.

يمكن استخدام `تحديث السرعات الآن` لقراءة واحدة دون بدء المراقبة المستمرة. إذا لم يتعرف التطبيق على الجدول، اضغط `فحص الصفحة وقراءة الإحصائيات` ثم `نسخ تقرير التشخيص` وأرسل التقرير.

## معنى القيم وحدود الاستنتاج

- `Uplink Rate` و`Downlink Rate` هي معدلات نقل البيانات التي يعرضها الراوتر في لحظة القراءة، بوحدة KB/s كما تظهر في صفحة Tenda.
- `Sent Bytes` و`Received Bytes` هي عدادات تراكمية كما يعرضها الراوتر، وليست استهلاك جلسة حديثة بالضرورة.
- ظهور معدل `0.00 KB/s` لا يعني أن الجهاز غير متصل؛ قد يكون متصلاً لكنه لا ينقل بيانات في لحظة القراءة.
- Traffic Statistics تعرض حركة البيانات حسب IP، وليست وحدها اختباراً مستقلاً يثبت الوصول إلى الإنترنت العام. قد تشمل حركة محلية أو بيانات من جلسات سابقة بحسب طريقة عد الراوتر.
- ربط IP باسم/MAC يعتمد على قراءة DHCP الحالية، أو آخر ربط محفوظ لمدة 24 ساعة. يعرض التطبيق العنوان التاريخي على أنه «آخر IP معروف» ولا يؤكده كعنوان حالي.
- هذا الإصدار لا يقدم بعد مخططاً زمنياً أو فرق العدادات بين قراءتين؛ يعرض القيم كما قرأها من الراوتر.

## الميزات السابقة

- لوحة مشتركين مع البحث بالاسم أو IP أو MAC والتصفية حسب DHCP/Wi-Fi.
- قراءة DHCP من `/lan_dhcp_clients.asp`.
- قراءة Wireless Connection Status من `/wireless_state.asp`.
- دمج DHCP وWi-Fi باستخدام MAC Address.
- حفظ أسماء مخصصة للأجهزة محلياً على الهاتف.

## حدود الإصدار

- وظيفة Static Assignment في هذا الإصدار للقراءة والفحص وتعبئة الحقول فقط؛ لا ينفذ التطبيق عمليات Add/Delete/OK تلقائياً. الحذف أو الحفظ يتمان يدوياً داخل صفحة الراوتر بعد مراجعة المستخدم.

- لا يوجد حظر أو تحديد سرعة أو جدولة مطبقة آلياً.
- تعمل المراقبة الحية أثناء بقاء التطبيق في المقدمة وبعد الضغط على «بدء المراقبة الحية». تتوقف مؤقتاً في الخلفية وتستأنف عند العودة.
- لا يتم إرسال طلبات كتابة إلى الراوتر.
- يجب التحقق من نتيجة القراءة على Firmware الفعلي قبل اعتبارها ناجحة.

## اختبار قواعد حجوزات IP

يمكن تشغيل اختبارات التحقق المستقلة على جهاز يحتوي على JDK فقط عبر `tests/run_ip_reservation_tests.sh`. وهي تختبر IP المستخدم من جهاز آخر، وتكرار MAC، والحجز الموجود مسبقاً، وعنوان الراوتر والشبكة المختلفة.

## بناء APK عبر GitHub Actions

ارفع محتويات هذا المجلد إلى جذر المستودع بحيث يوجد `settings.gradle` في الجذر، ويكون مسار Workflow هو `.github/workflows/android.yaml`. افتح Actions وشغّل `Build Tenda W303 Guard APK`، ثم نزّل Artifact باسم `TendaW303Guard-debug-apk`.

بيئة البناء: JDK 17، Gradle 8.7، Android Gradle Plugin 8.6.1، Android SDK 35.

## ملاحظات المراقبة الحية وحدودها

- المراقبة الحية ليست اتصالاً مباشراً بمستشعر سرعة مستقل؛ يعتمد التطبيق على قراءة قيم Uplink Rate وDownlink Rate التي يعرضها Firmware الراوتر بعد إعادة تحميل إطار الإحصائيات.
- الفاصل الافتراضي 3 ثوانٍ، ويمكن تغييره إلى 5 أو 10 ثوانٍ. زمن الاستجابة الفعلي قد يزيد عن الفاصل بحسب سرعة الراوتر ووقت تحميل الصفحة.
- تُحدّث المراقبة إطار `sys_iptAccount.asp` فقط متى أمكن التعرف عليه، ولا تعيد تحميل صفحة `advance.asp` كاملة.
- تتوقف المراقبة تلقائياً بعد ثلاث محاولات متتالية لا تجد جدول Traffic Statistics، أو عند الضغط على إيقاف. وتتوقف مؤقتاً في الخلفية وتستأنف عند العودة.
- لا يمكن ضمان تحديث أسرع من معدل أخذ العينات الذي يتيحه Firmware الراوتر نفسه. يجب قياس تغيّر القيم على الهاتف قبل وصفها بأنها لحظية تماماً.
- لا تزال الإحصائيات اليومية والشهرية غير مضافة في هذا الإصدار؛ ستبنى لاحقاً من فروق العدادات التراكمية المحفوظة محلياً.
