## الإصدار 0.2.13 — استعادة التنقل ومزامنة قوائم Tenda

### ما تم إصلاحه
- استعادة آلية الرجوع إلى إطار المحتوى الداخلي إذا لم يستطع التطبيق العثور على رابط الصفحة في قائمة الراوتر.
- فتح التبويب الرئيسي أولاً (Advanced / Wireless / Security / Tools / QoS)، ثم فتح الصفحة الفرعية بمسارها المعروف.
- محاولة قراءة رابط الصفحة الفرعية بمساره الدقيق عدة مرات لإتاحة وقت تحميل القائمة.
- استخدام رابط الصفحة الأصلي من قائمة Tenda عندما يكون ظاهراً، للمحافظة على تمييز القائمة الجانبية.
- الإبقاء على مسار الإطار الداخلي كحل احتياطي؛ لا يتوقف الاختصار لمجرد أن اسم الرابط الفرعي غير قابل للقراءة.
- جعل الفحص الكامل يبدأ من Advanced > DHCP Client List ثم ينتقل إلى Wireless > Wireless Connection Status، مع التحقق من مسار كل صفحة قبل قراءة الجدول.

### ما لم يتغير
- لم تتغير أسماء اختصارات الشاشة الرئيسية أو ترتيبها.
- لم تتغير خوارزمية قراءة DHCP أو Wi-Fi أو Traffic Statistics.
- لم تتغير أولوية المراقبة اللحظية لسرعة الرفع والتنزيل.
- لم تتم إضافة أي كتابة أو تعديل تلقائي لإعدادات الراوتر.
- لم يتم تعديل `.github/workflows/android.yaml`.

### مسارات الاختصارات
| الاختصار | التبويب | مسار الصفحة |
|---|---|---|
| قائمة أجهزة DHCP | Advanced | `/lan_dhcp_clients.asp` |
| الأجهزة اللاسلكية المتصلة | Wireless | `/wireless_state.asp` |
| السماح أو منع اتصال Wi-Fi (MAC) | Wireless | `/wireless_filter.asp` |
| تصفية المواقع وجدولة الوصول | Security | `/firewall_urlfilter.asp` |
| ضبط وقت الراوتر | Tools | `/system_hostname.asp` |
| QoS وتحديد السرعة | QoS | `/net_tc.asp` |
| QoS - Traffic Statistics | QoS | `/sys_iptAccount.asp` |

ملاحظة: مسار Wireless Connection Status (`/wireless_state.asp`) محفوظ من مسار البرنامج السابق، ويجب تأكيده على الراوتر الفعلي أثناء اختبار APK؛ بقية المسارات مدعومة بتقارير الصفحات وروابط واجهة Tenda التي زُودنا بها.

### الاختبار المطلوب بعد بناء APK
راجع `tests/ROUTER_LINK_AUDIT_AR.md` ونفذ اختبار الروابط السبعة. لا تعتمد النسخة كمنجزة قبل نجاح الاختبار على الراوتر.
